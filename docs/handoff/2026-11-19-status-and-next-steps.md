## 1. What this project is

Ultimate Util is a web platform of 33 everyday tools: documents, images, design, developer, everyday and cloud-synced tools. 27 tools run entirely in the browser with no login and no upload. 6 tools sync to the user's account after Google login (2FA codes, secure notes, snippets, saved palettes, clipboard drop, pomodoro/habits).

Owner decisions that shape everything:
- Light, minimal UI, palette **Ink + Electric Blue**, approved design in `design/home-a.html`.
- Monorepo, TypeScript everywhere, Docker, lightweight.
- Removed from scope by the owner: URL shortener, uptime/SSL monitor, currency rates.
- Real Google login comes later. For now a **mock login** (dev only) is used.
- Local MongoDB in Docker for testing. The owner will supply a MongoDB Atlas URL before production (`ATLAS_URI`).
- **No GitHub CI/CD for now.** Do not add `.github/workflows`.

## 2. Stack and layout

```
backend/   Fastify 5 + Mongoose, feature modules (auth, users, preferences, vault, encrypted, snippets, palettes, focus, clipboard, account, health)
frontend/  Next.js 16 (App Router), React 19, Redux Toolkit + RTK Query, plain CSS tokens
shared/    zod schemas and types shared by both (built to dist, consumed as @uu/shared)
docs/      specs (docs/features/**), decisions, changelog, this handoff
design/    approved home page mockup (visual source of truth)
docker-compose.yml   mongo (single-node replica set), backend, frontend, optional mongo-express (profile "dev")
```

Package manager: **pnpm 12** workspaces. Node 22+. pnpm 12 needs `allowBuilds` (already set for esbuild in `pnpm-workspace.yaml`).

Key conventions (see `docs/features/_shared/conventions.md`):
- **Tool registry** (`frontend/src/registry/meta/*.ts`) is the single source of truth. A tool is `status: 'soon' | 'live' | 'hidden'`. The home grid, command palette, counts, badges and `/tools/[slug]` all read from it.
- A tool is a folder `frontend/src/features/tools/<slug>/` with a default-exported client component in `index.tsx`, pure logic in separate tested modules. It goes live by (1) setting `status: 'live'` in its registry meta file and (2) adding one line to `frontend/src/features/tools/loaders/<category>.ts`. The reference tool is `word-counter`.
- Page frame, sign-in wall and vault unlock are applied automatically (`ToolShell`, `CloudGate`, `VaultGate`).
- Shared UI: `frontend/src/components/ui/*`, CSS vocabulary in `frontend/src/styles/globals.css`. Tool-specific CSS goes in a CSS Module inside the tool folder.
- Wasm/worker files are served from our own origin under `/vendor/...`. `frontend/scripts/copy-assets.mjs` copies them from `node_modules` into `frontend/public/vendor` (git-ignored, about 123 MB) before `dev` and `build`.
- Client tools must make **no network request containing user content**. No CDNs.
- Class A data (2FA entries, notes) is encrypted on the device (`frontend/src/lib/crypto/*`); the server stores only ciphertext.

## 3. How to run and verify

```
pnpm install
cp .env.example .env            # then set MONGO_URI for host use (see below)
docker compose up -d mongo      # local MongoDB (replica set rs0)
pnpm --filter @uu/shared build
pnpm dev:backend                # needs MONGO_URI=mongodb://localhost:27017/ultimate-util?directConnection=true
pnpm dev:frontend               # http://localhost:3000 (the owner's machine already uses 3000 for another app; use FRONTEND_PORT / -p 3100)
docker compose up -d --build    # full stack in containers (web on ${FRONTEND_PORT:-3000})
```

Checks that must pass before any commit:
```
pnpm --filter @uu/shared build
pnpm --filter @uu/backend typecheck && pnpm --filter @uu/backend test     # needs mongo running; 21 tests
pnpm --filter @uu/frontend typecheck && pnpm --filter @uu/frontend test   # unit tests
pnpm --filter @uu/frontend build
```

Mock login: `POST /api/v1/auth/mock-login` or the `/login` page ("Sign in as Alice Test"). It is refused when `NODE_ENV=production`.

## 9. How the review pass will audit your work

The auditor will check, per tool:
1. **Spec conformance:** the tool's spec in `docs/features/**` (user flow, inputs/outputs, edge-case table, acceptance criteria). Gaps must be declared in `NOTES.md`; undeclared gaps count as defects.
2. **Privacy:** no network request carrying user content from Local tools; no CDN; wasm from `/vendor`. Cloud Class A data never in plaintext off-device, never in logs or URLs.
3. **Security:** SVG/HTML sanitization, no `innerHTML` of untrusted content, no secrets persisted (JWT tool), CSRF header on writes, safe link handling in QR and clipboard tools.
4. **Correctness:** known-answer tests for crypto/hash/TOTP/contrast/cron/units; bad and empty input handled; large input does not freeze the UI (workers where the spec says).
5. **UX and accessibility:** labels, keyboard operation, aria-live, mobile width, dark mode, no color-only status.
6. **Quality:** types strict and clean, tests meaningful, small modules, no dead code or console logging.
7. **Git hygiene:** small commits, human-style messages, no secrets, no AI attribution, `.env` not tracked.
8. **Docs:** registry status matches reality; NOTES.md honest; changelog updated.

When you finish a stage, update `docs/03-changelog.md` with a dated entry listing what is done and what is not, so the audit can start from facts.
